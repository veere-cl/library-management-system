# Library Management System

Beginner-friendly Java 17 + Spring Boot 3 + Thymeleaf + Bootstrap + MySQL project.

## Features
- Librarian login using Spring Security and BCrypt password hashing.
- Dashboard counts and recent borrowing activity.
- Book and member CRUD, search, and validation.
- Issue/return workflow, due dates, overdue list, configurable daily fines.
- JSON REST API and common API error responses.
- Responsive Bootstrap pages and a development-only seed librarian/sample records.

## Requirements
- JDK 17+
- MySQL 8+
- Maven 3.8+ (or use the Maven wrapper generated by your IDE)
- VS Code with **Extension Pack for Java** and **Spring Boot Extension Pack**

## Run locally
1. Start MySQL.
2. Create the database (optional because the JDBC URL includes `createDatabaseIfNotExist=true`):
   ```sql
   CREATE DATABASE library_management;
   ```
3. Set database credentials in your terminal. PowerShell:
   ```powershell
   $env:DB_USERNAME="root"
   $env:DB_PASSWORD="your_mysql_password"
   $env:LIBRARIAN_PASSWORD="replace-this-password"
   ```
   macOS/Linux:
   ```bash
   export DB_USERNAME=root
   export DB_PASSWORD='your_mysql_password'
   export LIBRARIAN_PASSWORD='replace-this-password'
   ```
4. Open the project folder in VS Code.
5. Run:
   ```bash
   mvn clean test
   mvn spring-boot:run
   ```
6. Visit http://localhost:8080 and sign in as `librarian` with the password from `LIBRARIAN_PASSWORD`. If that variable is not set on first run, the local development default is `ChangeMe123!`.
7. Change the default password before sharing or deploying. The seed user is created only when the username does not exist; changing the environment variable after initial creation does not automatically update its password.

## Configuration
- `DB_URL`: defaults to local MySQL `library_management`.
- `DB_USERNAME`, `DB_PASSWORD`: database credentials.
- `LIBRARY_BORROW_DAYS`: default 14.
- `LIBRARY_DAILY_FINE`: default 2.00 per overdue day.
- `app.seed-demo`: default true; can be set to false to disable sample book/member data (seed librarian still initializes).

## REST API examples
All API endpoints require an authenticated session. Log in through the browser first or use Postman with cookie/session support. CSRF is disabled for `/api/**` in this local starter so JSON requests are straightforward; do not copy that setting blindly into a production deployment.

- `GET http://localhost:8080/api/books`
- `GET http://localhost:8080/api/books/search?keyword=clean`
- `POST http://localhost:8080/api/books` with JSON:
  ```json
  {
    "title":"Effective Java","author":"Joshua Bloch","isbn":"9780134685991",
    "category":"Programming","publisher":"Addison-Wesley","publicationYear":2018,
    "totalCopies":3,"availableCopies":3,"shelfLocation":"A-02"
  }
  ```
- `POST http://localhost:8080/api/members` with JSON:
  ```json
  {"fullName":"Anita Rao","email":"anita@example.com","phone":"9876543210","address":"Hyderabad","active":true}
  ```
- `POST http://localhost:8080/api/borrow/issue` with JSON: `{"bookId":1,"memberId":1}`
- `POST http://localhost:8080/api/borrow/1/return`
- `GET http://localhost:8080/api/borrow/issued`
- `GET http://localhost:8080/api/borrow/overdue`
- `GET http://localhost:8080/api/dashboard/stats`

Expected HTTP conventions: GET 200, successful POST 201 for creates/issues, successful DELETE 204, validation/business errors 400, missing entities 404.

## Troubleshooting
- **Access denied for user**: confirm DB_USERNAME/DB_PASSWORD and MySQL grants.
- **Communications link failure**: ensure MySQL service is running and port 3306 is available.
- **Port 8080 in use**: set `server.port=8081` in `application.properties`.
- **Unknown database**: create `library_management` manually.
- **Login rejected**: on first run, set `LIBRARIAN_PASSWORD`; if user already exists, delete/recreate the local `users` row or update the BCrypt password through a secure admin workflow.
- **Duplicate ISBN/email**: those fields are unique; use a new value.
- **Maven dependency resolution fails**: check internet connectivity and run `mvn -U clean test`.

## Important limitations / production hardening
This is a functional learning starter, not a production security review. Before production use, add a password-change/reset workflow, CSRF-safe API authentication, pagination, concurrency locking around copy counts, audit logs, stronger role administration, fine-grained report filters, and integration tests against a disposable MySQL/Testcontainers database. API error JSON and form error pages can also be expanded for a polished deployment.
